Dot Sim

Overview

An unofficial Kode Dot simulator in your browser. Play the apps, open their code, change it, and run your version a few seconds later. Nothing to install.

The sim runs the real kode-sdk, built for Linux instead of the ESP32-P4. Your code is compiled on the server in a sandbox and runs there too; the browser only shows the screen and sends the buttons and touches.

Controls

D-pad← ↑ → ↓the d-pad on the picture
TOP (blue)Zthe blue button
BOT (red)Xthe red button
Touch screen—click, drag or tap the screen

Holding TOP and BOT together for one second leaves an app. Sound is off until you switch it on (browsers only allow sound after a click).

Editing code

  1. In the Code panel, pick New app (starter) or the code of one of the games.
  2. Change the code. The kk.h tab lists everything you can call.
  3. Press Build & run (or Ctrl+Enter). The first build takes about 10–30 seconds; your app then starts on the Dot.
  4. Errors from the compiler show up as red lines in the editor and in a list below it. Click one to jump to the line.

Your edits are saved in your own browser, per app, so they are still there when you come back. Reset goes back to the original code; Download saves your app_main.c.

You edit app_main.c: one C file that is the whole app. The build files, kodekit (kk.c, kk.h) and the SDK stay the same, so every app you write here uses kodekit to draw.

How an app works

An app paints whole frames itself. The loop is always the same: kk_begin() waits for the screen, reads the buttons and touch, and gives you a fresh frame to draw in; kk_end() shows it. That runs about 60 times a second.

#include <stdio.h>

#include "kode.h"
#include "kk.h"

KODE_APP_MANIFEST("My App", "games");   // name and category

void app_main(void)
{
    kk_init();                           // start the board, once
    for ( ;; )
    {
        kk_begin();                      // input + new frame
        kk_clear(KK_BLACK);
        kk_text_c(230, "HELLO", 4, KK_WHITE);
        kk_end();                        // show it
    }
}

The screen is 410 × 502 pixels, (0, 0) at the top left. The glass has round corners: keep text at least KK_SAFE_X (40) from the sides and KK_SAFE_Y (36) from the top and bottom. Colours are RGB565; make your own with KK_RGB(r, g, b).

Keep state in static variables or locals outside the loop, and do the game logic between kk_begin() and drawing. Use kk_ms() for time, so the speed does not depend on the frame rate.

Examples

A bouncing ball

void app_main(void)
{
    kk_init();
    float x = 205, y = 250, vx = 3.1f, vy = 2.3f;
    for ( ;; )
    {
        kk_begin();
        x += vx; y += vy;
        if ( x < 60 || x > 350 ) { vx = -vx; kk_tone(660, 20); }
        if ( y < 60 || y > 440 ) { vy = -vy; kk_tone(440, 20); }
        if ( kk_pressed(KK_TOP) ) { vx *= 1.2f; vy *= 1.2f; }
        kk_clear(KK_DARK);
        kk_disc((int)x, (int)y, 18, KK_CYAN);
        kk_end();
    }
}

A counter with a high score

static long count, best;

void app_main(void)
{
    kk_init();
    best = kk_best_get("taps");
    for ( ;; )
    {
        kk_begin();
        int tx, ty;
        if ( kk_tapped(&tx, &ty) || kk_pressed(KK_TOP) ) { count++; kk_buzz(15); }
        if ( kk_pressed(KK_BOT) ) { count = 0; }
        if ( count > best ) { best = count; kk_best_put("taps", best); }
        kk_clear(KK_BLACK);
        kk_num_c(200, count, 8, KK_WHITE);
        char b[32];
        snprintf(b, sizeof(b), "BEST %ld", best);
        kk_text_c(300, b, 2, KK_GREY);
        kk_end();
    }
}

More: open the code of any game in the editor. Snake, Wall Breaker and Block Rain are good ones to start from.

Limits

  • One build at a time per visitor; a build may take up to 3 minutes. Code up to 64 KB.
  • Up to 4 sims run at the same time for everyone together. If you see “too many sims”, try again in a minute.
  • Built apps are kept for about 6 hours. Your code itself stays in your browser; download it to keep it for good.
  • The sim has no Wi-Fi, Bluetooth, NFC or other radios. The Kode Link (kk_link_*) only connects devices of a logged-in user.
  • Your code runs in a sandbox without network access.
